# Swift runtime functions the app may import strongly.
#
# scripts/check-runtime-imports.sh fails the release when the app binary
# imports a Swift runtime function (a C symbol starting with _swift_, from
# /usr/lib/swift/libswift*.dylib) strongly and it is not listed here. A strong
# import of a function the user's macOS lacks stops dyld from loading the app at
# all, as _swift_initBorrow did below macOS 27 (WH-16).
#
# Every function listed must exist in the Swift runtime of the minimum macOS
# declared in Package.swift and Resources/Info.plist (14.0, Swift 5.9). The
# initial list is the strong imports of 0.9.0 (build 47) without
# _swift_initBorrow, plus _swift_copyPOD (a value-witness helper since Swift
# 5.0, imported by the WH-16 reproducer); the "2" variants (conformsToProtocol2,
# getTypeByMangledNameInContext2 and InMetadataState2) arrived with Swift 5.9.
#
# Before adding a function, confirm that the runtime of the minimum macOS
# exports it, for example by running on a Mac with that macOS:
#   dyld_info -exports /usr/lib/swift/libswiftCore.dylib | grep <symbol>
# If it does not, weak-link it in Sources/WeakRuntimeImports instead.
